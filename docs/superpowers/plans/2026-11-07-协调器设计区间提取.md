# 协调器设计区间提取实施计划

**目标** 在 Graph V2 的现有协调请求中提取任务所指的设计区间，给工程工具传入已核验的起终点。

**实现** 扩展 `CoordinatorDecision` 的模型输入契约。模型摘录原文中的完整区间，`bridge_agents/utils.py` 负责核对原文、单位和顺序，再由图节点写入既有桩号字段。已有成对工程状态优先。区间缺失且初设需要原始路线资料时走人工复核。

**基线** `4c853cd300f3bc69f7fbec9dfda23dd61df7f3d8`。使用 Python、pytest 和 LangGraph。保留兼容图和工程裁剪接口。本轮只使用离线替身，不发真实模型请求。

- [ ] 在 `tests/test_graph_v2.py` 验证协调器从包含障碍桩号的任务中选中正确区间，向初设传入 `K12+200` 和 `K13+050`，并验证无可靠区间时的复核路由。
- [ ] 在 `bridge_agents/design_coordinator.py` 和角色 Skill 定义 `design_range` 为原文中的完整连续摘录，不能确定时返回空值。通过 `bridge_agents/utils.py` 解析桩号、米和公里写法，校验区间并将字段传入图状态。离线或旧响应仅对明确的单一区间兜底。
- [ ] 用独立临时目录运行协调器、Graph V2、人工复核、桩号和入口回归。记录基线、测试案例、模型请求用量和未验证边界，单独提交结果。
